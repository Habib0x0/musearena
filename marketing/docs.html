Quickstart

Run the console and designer locally, then generate your first environment.

cd backend && npm run build
node --env-file=../.env dist/designer/server.js

cd frontend && npm run dev -- --host 0.0.0.0 --port 5173

Open the console, sign in, and describe an organization. Review the topology, build plan, and cost before approving a deployment.

Core concepts

TermMeaning
EnvironmentSpecCanonical JSON describing hosts, services, personas, weaknesses, and objectives.
Readiness probeA check that a service actually works, often run from a peer guest.
CanaryA per-host proof that its sensor sees a fresh event.
ObjectiveA measurable goal with a verifiable success signal.
Ground truthHash-chained evidence that lets a dataset be replayed and re-scored.

Verification

Every run is gated on evidence. A sensor that cannot see is a failed run, not a low score.

  • Readiness probes per host and cross-host
  • Canary events with fresh nonces
  • Benign control runs for false-positive baselines
  • Objectives rejected when no verifiable signal exists

Datasets

Exports are content-hashed and version-pinned. Re-download the dataset, verify the hash, and replay the score offline.

node scripts/org-demo-replay.mjs

Replay reproduces the same objectives and false-positive rate without touching a live guest.
